## Recent Decisions

- Standard completion procedure: after every Weekly Logger project task, update this shared handoff with the task result and current project status, including what changed, branch and commit information, files changed, test results, risks, and whether the work is merged or awaiting review. Commit and push the handoff-only update to this shared GitHub repository, then verify the remote commit so ChatGPT can retrieve it without a separate verbal handoff. Follow an explicit contrary instruction when one is given.
- Monthly Drafts email suppression is fulfillment-specific: Boxes sites default to 30 days from the most recent applicable boxes sent (`BoxOrder`) activity date, and Labels sites default to 14 days from the most recent applicable labels sent (`ShippingLabel`) activity date. A Boxes site receiving both in one fulfillment records both activities but remains controlled by the Boxes activity and period. Both settings accept only 0 through 90 days; zero disables the applicable clock. The confirmed per-run override remains non-persistent, and every decision is logged.
- Site names and aliases are limited to 100 trimmed characters in UI, repository validation, and schema triggers. Migration v22 aborts rather than truncating if existing data exceeds that limit.
- New or changed US phone values accept common formatting and extensions, normalize the main number to digits, and require 7 or 10 digits, or 11 beginning with 1. Eight- and nine-digit US numbers are rejected. Non-US values do not use US length rules, duplicate matching uses the same normalization without cross-context US/non-US matches, and unchanged legacy values remain editable.
- Agreement per-unit amounts are capped at $100 in UI and repository validation. The former $1,000,000 UI maximum had no dependent business logic. Payment type `Check` is now `Payment`; migration v22 and the repository compatibility path preserve existing behavior.
- Order-form templates must contain the exact `Order Form` worksheet and merged structural anchors `C8:D8` and `H12:J12` before any output is written. Fields are not auto-mapped.
- Microsoft Graph retains its 60-second timeout. Controlled smoke draft creation may retry once after a timeout not caused by caller cancellation; real batch draft creation never retries automatically.
- Order-processing To/CC recipients are configured in CRM Settings. The optional approval send checkbox is off by default; approval is committed before Graph send, so an email failure does not reverse approval.
- Monthly Drafts has a one-message real-send test requiring an explicitly entered, non-persisted recipient. Graph authentication uses a persistent DPAPI CurrentUser-protected MSAL cache for silent authentication before interactive fallback.
- A contact email is not globally unique. The same normalized email may be used at multiple sites when intentional.
- Reused-email detection is advisory: show the associated sites and allow the save to continue.
- The reused-email advisory is a pre-save Yes/No confirmation, not a validation error. Yes saves all pending changes; No saves nothing and leaves the edits available for correction.
- `DT Associate` changes are confirmed through the normal status bar only and are omitted from modal save summaries.
- The source recycle-call-list workbook is not copied into the application output and is not used for a startup postal-code backfill.
- Agreement records and their site assignments are stored in the CRM database; agreement documents remain managed through the configured document-storage workflow.
- Workbook export paths are configured on the `Order forms` settings tab. Both paths must be set together and must identify separate workbooks with the expected target sheet and headers.
- Manual export replaces only the matching worksheet table rows, preserves workbook formatting and unrelated worksheets, and does not modify the database. Active sites without contacts still receive an RCLog row so site data is not omitted.
- Google geocoding is intentionally on hold while the Google account work is deferred. It is not a release blocker and should not be run unless the user reopens that work.
- The automatic database backup folder is chosen in Settings. CRM checks daily, creates a verified backup when the newest is at least seven days old, and retains the newest 10 managed backups.
- Duplicate candidates are advisory. A merge requires explicit confirmation, creates a backup first, preserves the chosen survivor, moves related associations and history transactionally, fills only blank survivor fields, and archives the duplicate.
- Schema 19 deletion-batch tokens ensure restoration reverses only the selected delete operation and does not revive records that were already inactive.
- CRM is the authoritative Monthly Drafts recipient source. An eligible site is active under an active company and has at least one valid active email; invalid addresses are excluded and sites with no valid address are skipped.
- CRM opens Monthly Drafts as an owned modal window. The standalone Monthly Drafts executable remains supported and resolves `Data\CRM.sqlite` beside the application unless `CRM_DATABASE_PATH` is set.
- Every verified monthly draft records one idempotent CRM `FollowUp` activity dated with the current local date. A verified draft is retained when follow-up recording fails, and the next run reconciles the missing follow-up without creating another draft.
- The Graph Draft ID does not need to appear in the CRM History tab. Future UI work should hide that implementation detail while retaining the identifier in internal audit data and diagnostic logs when it is useful for support or reconciliation.
- The intended next evolution is to rename Monthly Drafts to Monthly Inquiry and send the emails rather than only creating drafts. The user wants a simpler interface because the draft workflow has proven reliable, while keeping detailed operational logging behind the scenes. Sending safeguards and recovery rules still need to be defined before implementation.
- Monthly Inquiry will require a final confirmation before live sending. Its simplified processing view must show sent messages versus total, percent processed, and the current recipient as `Company - City, State/Province, Country`. Graph connectivity and single-recipient test-send controls remain available only under Advanced/Diagnostics.
- Add application-level password protection shared by CRM and standalone Monthly Inquiry; database encryption is out of scope for now. `Robert Nevins` is the initial administrator. Preserve a future-ready user/role/permission model so an administrator can later add users, assign roles, and control function access through a management form.
- An administrator session may open protected Monthly Inquiry functions without another password prompt. A non-administrator must supply an administrator password. Every privileged use must audit the acting user, authorizing administrator, protected function, timestamp, and outcome without storing or logging the password.
- The authenticated user automatically becomes the read-only `DT Associate` for newly added sites and for actual site or contact changes saved for the selected site. Company-only changes do not rewrite all company sites. A successful Monthly Inquiry send also attributes the site to the authenticated user.
- Each eligible site is one Monthly Inquiry message even when it has multiple recipients. A failed message does not stop the batch; processing continues, reports failures, and a later run retries only failed or unsent sites.
- Monthly Inquiry requires separate Pause/Resume and Stop controls. Its progress area also exposes the current monthly-cycle duplicate-prevention state so the user can see which eligible sites were already sent and will not be sent again without an Advanced override.
- First-run authentication will require Robert Nevins to enroll an administrator password and receive a one-time recovery code. Administrator elevation applies to one requested action only, followed by a message explaining what was authorized. Initial administrator permissions cover live Monthly Inquiry sending, same-month resend override, database restore, duplicate merging, future user/role management, Settings, and data export.
- Audit successful and failed login/elevation attempts. In addition to application identities and the protected function, capture the Windows user, computer name, and available local IP addresses. Never store or log the supplied password or recovery code.
