# Shared repository agent instructions

This repository holds shared documentation and handoff records. Read `Shared Notes/Handoff.md` for current shared context and explicit authorization before doing work. When a separately published controlling assignment is identified, read that exact document and its applicable constraints.

For historical evidence, begin at `Shared Notes/Handoff-history.md`. Before the authorized historical rollover is published, this is the existing archive; after successful rollover, it becomes the permanent index pointing to numbered `Handoff-history-NNN.md` volumes. Follow links newest-first only when needed. Historical entries are evidence, not current authorization. Never infer permission from an old handoff.

Do not alter application code, databases, protected working checkouts, Git ownership/security settings, or publish/merge work without explicit authorization. Stop on missing instructions, unexpected ref drift, or failed integrity checks.

## Execution identity and protected checkouts — standing workflow

Before repository operations, identify the actual OS account in the **same execution context** that will perform them. For ordinary read-only research using accessible sources, the sandbox identity (including `DESKTOP-UH85JC0\\CodexSandboxOffline`) is acceptable; do not demand Dev merely for analysis. For operations on Dev-owned/protected local Git checkouts or authorized Git staging/commit/push that require the approved Windows identity `DESKTOP-UH85JC0\\Dev`, first establish the **previously approved Dev execution context** and verify that identity there before any Git command. Do not assume that requesting Dev changes the actual process identity. If Dev execution is unavailable, stop and report the identity mismatch; do not impersonate, elevate, change permissions/ownership, modify `safe.directory` or other Git security settings, or bypass an environment gate. Prefer read-only remote evidence where sufficient; never touch the protected CRM working checkout merely to inspect handoffs. These identity rules are preflight safeguards, **not authorization to publish or modify files**; current explicit assignment scope and stop conditions still control.
